FolderSync — 跨平台文件夹同步工具

一个基于 Python + PyQt6 的轻量级目录同步工具，支持 Windows <-> Windows（共享）
与 Ubuntu -> Windows 共享（SMB）两种典型场景。
既是实用小工具，也是我学习 GitHub 协作与发布流程的入门项目。


================================================================================
项目背景
================================================================================

在日常开发中，我经常需要在两台机器之间同步文件夹：

- Windows -> Windows：一台 Windows 通过共享文件夹访问另一台 Windows，做双向同步
- Ubuntu -> Windows：Ubuntu 通过 SMB 挂载/访问 Windows 共享，将远程目录同步到本地

为了避免重复手动复制，我写了这个小工具。同时，这也是我第一次完整使用 GitHub
提交代码、打 Tag、发 Release，为后续项目积累经验。


================================================================================
功能特点
================================================================================

- 双模式运行：
    命令行模式：带两个目录参数，直接同步，无界面
    图形界面模式：不带参数启动时，弹出 PyQt6 窗口，可视化选择目录

- 跨平台：Windows 生成 .exe，Ubuntu/Linux 生成无扩展名可执行文件

- 智能同步逻辑：按文件修改时间比较，较新文件覆盖较旧文件

- DEL_ 前缀删除指令：以 DEL_ 开头的文件/目录会触发跨目录定向删除

- 时间差防回拷：内置时间容差机制，避免刚同步的文件因时间戳偏差被反向拷贝

- 命令回显：GUI 同步完成后，底部显示本次同步的完整终端命令，一键复制

- 网络路径友好：支持 Windows 共享路径（//tsclient/）、SMB 路径（smb://）

- DEL_ 前缀可配置（自定义前缀）

- 时间容差值可配置

================================================================================
打包为独立应用
================================================================================

Windows -> FolderSync.exe：

    cd folder_sync
    pyinstaller --noconfirm FolderSync.spec

输出：dist\FolderSync.exe

Windows 服务所需的 pywin32 模块由 `FolderSync.spec` 显式打包；请使用该配置构建
Windows 版本，不要改用不包含服务依赖的旧式单行命令。


Ubuntu / Linux -> FolderSync：

    pyinstaller --onefile --name "FolderSync" folder_sync.py

输出：dist/FolderSync

注意：打包前确保已安装 pyqt6 相关依赖，且 PyInstaller 版本 >= 5.0

使用说明
================================================================================

模式一：命令行直接同步（带参数）

    FolderSync <目录A> <目录B>

程序直接执行同步，不弹窗，适合脚本或定时任务。


模式二：图形界面（无参数）

    FolderSync

启动 PyQt6 窗口：
1. 点击"选择目录 A"和"选择目录 B"
2. 点击"开始同步"
3. 同步完成后，底部"终端命令"区域会显示本次同步对应的命令行指令
4. 点击"复制命令"，可直接粘贴到终端中执行（方便下次复用）


================================================================================
Windows 定时同步服务
================================================================================

服务功能仅在 Windows GUI 中提供，不改变 Linux、GUI 手动同步或两个目录参数
的命令行同步方式。必须先在当前 GUI 窗口选择目录 A/B 并成功完成一次同步，
之后“创建并启动服务...”按钮才会启用。服务的同步逻辑与 GUI/命令行共用，
包括 DEL 前缀处理、时间戳比较和路径解析。

创建流程：

1. 以管理员身份启动 FolderSync，完成上述一次成功的 GUI 同步。
2. 设置正整数同步间隔（分钟），点击“创建并启动服务...”。确认对话框会列出
   最终服务名、两个目录、周期和将使用的 Windows 账户。
3. 确认账户信息后，在密码框输入该账户密码。密码只传给 SCM 配置服务账户，
   不会保存到配置、命令行或日志。
4. FolderSync 通过 Windows 服务控制管理器安装真正的 Windows Service 并立即
   启动，启动类型设为“自动”。服务启动后立即进行第一轮同步；每轮完成后再
   等待所设分钟数，然后开始下一轮，因此运行时间会加在两轮开始时间之间。
5. 界面服务列表只显示通过 FolderSync 标记、服务配置和入口命令共同验证的
   服务。刷新列表后选中服务并点击“删除服务”，确认后程序会先停止运行中的
   服务，再调用 SCM 删除注册。Windows 可能因服务句柄仍打开而延后完成删除。

服务名称以 `Folder` 加目录 A 的最后一级文件夹名生成。例如
`E:\Data\Python` 得到 `FolderPython`。Windows 服务名非法字符会替换为下划线；
名称冲突时自动追加序号（如 `FolderPython2`），并在确认前展示最终名称。

权限和网络路径：

- 创建、启动、停止和删除 SCM 服务都要求管理员权限。未提升时程序会明确提示
  以管理员身份重新运行，不会尝试绕过 UAC。只读服务列表通常不要求提升；若
  当前账户没有查询权限，界面会报告错误。
- 服务以确认的当前 Windows 登录账户运行（而非 LocalSystem），需要输入该账户
  密码。若账户没有“作为服务登录”权限，Windows 会拒绝启动；请由管理员在
  本机安全策略的“用户权限分配”中授予该权限，然后重试。程序不会静默改用
  其他账户或降低安全性。
- 服务不会继承用户交互式登录会话中映射的盘符。网络目录请配置 UNC 路径，例如
  `\\server\share\folder`；映射盘符即使在 GUI 中可用，也可能无法被服务访问。
  当前账户还必须拥有共享权限和目标目录的 NTFS 权限。
- 服务依赖安装时记录的应用程序绝对路径；服务安装后不要移动或删除
  `FolderSync.exe`。如需更换位置，请先从 GUI 删除服务，再从新位置重新创建。
- 服务配置存放于 `%ProgramData%\FolderSync\services`；按服务分开的运行日志位于
  `%ProgramData%\FolderSync\logs\<服务名>.log`。密码不写入这些文件。

排错：

- 服务账户/密码错误：重新创建时确认当前登录账户及密码；账户锁定或密码过期时
  先按组织策略解除。服务登录失败不会自动切换账户。
- “作为服务登录”错误：请管理员授予该账户相应用户权限后，在 GUI 刷新状态，
  再尝试启动/重建服务。
- 启动失败：GUI 会报告“已安装但启动失败”，不会误报创建成功，并可选择立即
  删除该服务；也可在服务列表检查状态后再删除。
- 同步失败或路径不可达：查看上述服务日志中的时间、同步结果和错误；确认目录
  仍存在、服务账户可访问，并针对网络位置检查 UNC、共享权限及 NTFS 权限。
- SCM 删除可能延迟：关闭仍打开该服务属性或管理句柄的工具后刷新列表；不要把
  “停止服务”当作“删除服务”。

实际使用场景示例
================================================================================

场景 A：Windows -> Windows 共享（通过 //tsclient/）

Windows 通过远程桌面共享驱动器访问另一台 Windows：

    FolderSync.exe E:/c_temp_u/DEL_BlankApp14 //tsclient/E/c_temp_u/DEL_BlankApp14

参数说明：
- E:/c_temp_u/DEL_BlankApp14          本机 Windows 目录
- //tsclient/E/c_temp_u/DEL_BlankApp14  通过远程桌面映射的另一台 Windows 共享目录


场景 B：Ubuntu -> Windows 共享（通过 SMB）

Ubuntu 通过 SMB 协议访问 Windows 共享文件夹：

    ./FolderSync '/home/weng3998/公共/PythonDemo/test/sub2' 'smb://it001va3721.local/python/sub6'

参数说明：
- /home/weng3998/公共/PythonDemo/test/sub2   Ubuntu 本地目录
- smb://it001va3721.local/python/sub6         Windows 共享目录（SMB 协议）

注意：Ubuntu 下需确保已安装 gvfs-backends 或 cifs-utils，且 SMB 路径可正常访问。


================================================================================
同步逻辑详解
================================================================================

1. 文件同步（基于修改时间）

- 遍历两个目录下的所有文件（含子目录）
- 按修改时间（mtime）比较两端同名文件
- 较新的文件覆盖较旧的文件
- 仅同步文件内容，不自动删除目标目录中多余的文件

时间差防回拷机制：

由于文件拷贝后两端时间戳可能存在微小偏差（尤其是跨文件系统/网络），
程序内置了一个时间容差窗口：

- 如果文件从 A 拷贝到 B 刚完成，B 端文件的时间戳与 A 端原始文件差异
  在容差范围内
- 程序会识别为"同一次同步产生的文件"，不会将其反向拷贝回 A
- 这样可以避免：A 拷到 B -> 因时间差 -> B 又拷回 A 的死循环

时间容差值当前可在程序中配置。


2. DEL_ 前缀删除指令

这是本工具的一个特殊设计，用于跨目录定向清理。

规则：

- 同步过程中，如果发现任意一端存在以 DEL_（不区分大小写）开头的文件或目录：
  1. 程序提取 DEL_ 后面的部分（例如 DEL_test.txt -> test.txt）
  2. 到对端目录中寻找同名文件/目录
  3. 如果找到，先删除对端的对应文件/目录
  4. 然后删除本端的 DEL_ 文件/目录本身

示例：

  本端（A）           对端（B）             行为
  DEL_test.txt        test.txt 存在       ① 删除 B 端的 test.txt
                                             ② 删除 A 端的 DEL_test.txt

  DEL_test.txt        test.txt 不存在     仅删除 A 端的 DEL_test.txt

  DEL_old_folder/     old_folder/ 存在     ① 删除 B 端的 old_folder/
                                             ② 删除 A 端的 DEL_old_folder/

设计意图：

  当你想通知对端删除某个文件时，只需在本端放一个 DEL_ 前缀的占位文件，
  同步完成后，两端都会清理干净。非常适合跨机器协作中"我删了，你也删"的场景。

注意：DEL_ 操作是不可逆的，请谨慎使用。
DEL_ 前缀字符串当前可在程序中配置，不限于默认的 "DEL_"。
